# Evaluation — 2026-11-15

Экспериментальная оценка single-turn маршрутизации. **Это не независимый production benchmark и не доказательство равного общего качества моделей.** Все условия синтетические, подготовлены AI-агентами. Эталоны локально проверены кодом. Числа получены из сохранённых результатов, не придуманы.

## Протокол

- Основные модели: cheap = Claude Haiku 5.5, strong = Claude Opus 5.5; router выбирает Haiku / GPT-6.1 Sol / Sonnet / Opus.
- Единые max_tokens=2048, temperature=0 и системная инструкция формата ответа. Без инструментов, streaming и исполнения модельного кода.
- Strict exact/JSON и normalized (одна внешняя Markdown-обёртка) зафиксированы до этих двух прогонов. Во всех приведённых результатах обе метрики совпали.
- Стоимость — `usage.cost_rub`, сообщённая Polza, не независимая сверка баланса. Включены Jev и vision-анализ; неизвестных расходов в этих прогонах нет.
- Средняя задержка — wall-clock всей стратегии; router включает vision/Jev. Порядок стратегий фиксированный, нет рандомизации и повторений. Часть двух наборов исполнялась параллельно; возможны эффекты нагрузки и provider caching, поэтому задержки не считать контролируемым сравнением.
- Модели получали только задачи/картинки, без эталонов. Финальный test запускался один раз. Это заранее выделенный **публичный** test, не скрытый независимый holdout.

## Интерпретация без выборочного представления

- На extended-dev роутер получил 27/28, как фиксированный Opus, при меньшей стоимости на 54.5%. Haiku — 22/28. Router выбрал Haiku в 2 задачах, Sol в 21, Opus в 5; Sonnet не выбирался.
- **Все незачтённые extended-ответы имеют finish_reason=length.** Здесь измеряется надёжность под фиксированным токеновым бюджетом (включая reasoning), а не качество при неограниченном времени/расходе. Это существенное ограничение: нельзя приписывать разницу только лучшему рассуждению. Повышать лимит после просмотра ответов и выдавать новый прогон за тот же эксперимент нельзя.
- На маленьком test router и Haiku — 14/15, Opus — 15/15. Router существенно дороже Haiku и не улучшает strict accuracy. Единственная ошибка router — содержательно неверный численный ответ test-02; у cheap там правильный ответ сопровождается запрещёнными пояснениями. Одинаковая доля совпадений не означает одинаковые ошибки.
- На всех визуальных задачах этих наборов все стратегии дали строгие совпадения. Поэтому преимущество vision-предобработки относительно её отсутствия **не установлено**: нужен ablation. Image-only и несколько картинок функционально прошли, но HTTP-путь реального клиента этим single-turn benchmark не проверяется.
- Совокупно два прогона: 69.19087706 RUB; со всеми ранними dev-пилотами: 77.59014792 RUB по API.

## Продолжение extended-dev

После ext-algo-05:strong runner остановился: API cost превысила прогноз этого вызова (4.77705601 против 4.407758818848 RUB). Это не исчерпание общего бюджета.

Исправлен только бюджетный учёт runner: теперь известное превышение резерва учитывается против общего локального лимита. Явное продолжение пропустило 14 готовых ячеек; **ни один готовый ответ не перезапрашивался**. Модели, промпты, scoring и данные неизменны. Исходный manifest сохранён, хеш runner продолжения записан отдельно. Vision ещё не вызывался до остановки, поэтому холодный кеш продолжения не изменил повторное использование изображений.

Исходный финальный test выполнялся исходной версией runner без остановок. Таким образом бюджетная обвязка двух прогонов различалась, оценочный протокол — нет.

## Воспроизводимость и пределы вывода

[Машиночитаемый отчёт](evaluation-2026-11-15.json) содержит сравнение по каждой задаче, выбранные модели, ответы, costs, хеши протокола и конфиг. Это проверенные синтетические тексты без пользовательских данных; сырые API-журналы остаются локальными и исключены из Git.

Исходные данные: `benchmark/data/` и `benchmark/extended/data/`. Проверка extended: `python3 -m benchmark.extended --check`. Для повторного анализа локальных артефактов: `python3 -m benchmark report --out <run-directory>`; это бесплатно. Новый `run` платный, требует отдельного бюджета и согласования. Совпадение ответов внешних моделей при повторе не гарантируется.

Наборы малы, один запуск, без доверительных интервалов, rule-based baseline и vision ablation. Прежний dev использовался для отладки формата/лимита; extended публичный диагностический dev. Нет реальных agent/tool-use задач, реального трафика и проверки многоарендности. Отдельные upstream каталога неофициальные. Не заявлять глобальную экономию или production readiness на основании этих таблиц.
