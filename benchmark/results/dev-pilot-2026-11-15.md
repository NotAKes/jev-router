# Dev pilot: new evaluation protocol

Дата: 2026-11-15. Набор: 15 dev задач (12 текстовых, 3 PNG), три стратегии, один последовательный прогон. Финальный test не запускался.

## Протокол

- Единый max_tokens=2048, temperature=0, без инструментов и streaming.
- Единая системная инструкция формата ответа для основных моделей.
- Strict и normalized (strict-v1+outer-wrapper-v1) зафиксированы до этого прогона.
- Никаких изменений эталонов, порогов Jev и критериев tiers после первого пилота.
- Маршрутизатор: оригинальные изображения основной модели, отдельный vision-анализ для Jev; его стоимость включена.
- Время включает последовательные вызовы маршрутизации. Порядок cheap → strong → router фиксированный, без рандомизации. Возможны эффекты provider caching, различного upstream и текущей нагрузки.

| Стратегия | Strict | Normalized | Обрезания | API cost, RUB | Среднее время, s |
|---|---:|---:|---:|---:|---:|
| cheap | 14/15 | 14/15 | 0 | 0.11712061 | 1.39 |
| strong | 15/15 | 15/15 | 0 | 3.29673629 | 2.62 |
| router | 14/15 | 14/15 | 0 | 0.69553780 | 3.20 |

Все стратегии: 4.10939470 RUB по usage.cost_rub. Это сообщённая API стоимость, не независимая сверка баланса. Включая оба предшествующих запуска: 8.39927086 RUB.

## Вывод

Обрезания исчезли. Strict и normalized совпадают. Единственная незачтённая задача у cheap и router — dev-02: правильный численный результат 253 сопровождается пояснениями. Правило нормализации не удаляет пояснения и не менялось ради этого ответа.

Router на 78.9% дешевле strong, но на этом наборе имеет ту же strict accuracy, что cheap, при стоимости в 5.94 раза выше и большей задержке. **Польза маршрутизации относительно фиксированной дешёвой модели пока не продемонстрирована.** Нельзя выдавать только сравнение с Opus за доказательство преимущества роутера.

Набор слишком мал и прост для проверки сложных tiers; Sonnet и Opus не выбирались. Это диагностический dev-пилот, не репрезентативный результат и не независимая оценка. Одновременно изменены инструкция и лимит, поэтому приписывать улучшение только одному из них нельзя.

## Дальше

До финального test определить, оставляем ли этот небольшой набор smoke-тестом или расширяем dev более сложными проверяемыми задачами. Не усиливать искусственно маршрутизацию на дорогие модели ради красивого результата. Для убедительного эксперимента нужны разнообразие задач, rule-based baseline, ablation vision, повторения и неопределённость оценки.

Сырые результаты и воспроизводимый manifest с хешами находятся локально в benchmark/runs/pilot-dev-20261115-v3/ (исключён из Git). Этот агрегат не содержит ключей, пользовательских сообщений или идентификаторов аккаунта.
