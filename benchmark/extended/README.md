# Extended dev: reproducible diagnostic tasks

Добавлены **28 отдельных dev-задач**. Старые `benchmark/data/cases.jsonl` и шесть PNG не менялись; исходный публичный test остаётся нетронутым. Это не новый скрытый test и не репрезентативный срез пользовательских запросов.

## Состав

- **12 алгоритмических:** взвешенное расписание и количество оптимумов, кратчайшие пути, топологические порядки, рюкзак, оптимальные выравнивания строк, строковые ограничения, точки сочленения, конденсация SCC, поток/min-cut, подмассивы, модульная динамика и назначения.
- **10 задач анализа данных:** дедупликация версий и tombstones, event-time окна, возвраты/кешбэк, SQL LEFT JOIN с NULL, confusion matrix/F1, утечка между группами, сортировка NULL, взвешенные когорты, транзакционные остатки и сессии событий.
- **6 визуальных:** соединение двух таблиц по ключу, два image-only сообщения, пути по клеткам с препятствиями, счёт со скидками, расписание по изображению. Всего 7 PNG; инструкции в image-only находятся только на картинке.

Предполагаемая сложность не измерялась моделями. Часть задач специально простая: проверяет границы пайплайна, а не математику. Не назначаем эталонный tier и не заставляем роутер выбирать дорогую модель.

## Происхождение и воспроизводимость

Все примеры и данные синтетические, подготовлены AI-агентами специально для проекта; это не пользовательские логи и не сторонние задачи. PNG растеризуются локально с оригинальным bitmap-шрифтом без внешних ресурсов. Код и оригинальные данные распространяются по [MIT](../../LICENSE).

Исходники генерации: `algorithms.py`, `data_tasks.py`, `vision.py`. Эталоны вычисляются локальным кодом и перекрёстно проверяются альтернативной реализацией: DP против перебора, поток против перебора разрезов, SQLite против Python и т.д. Для простых image-only вычислений используется обратная операция/повторное суммирование; это не сильная независимая проверка содержания картинки. Проверки кода не заменяют независимое человеческое ревью условий. Таблица и сетка дополнительно просмотрены визуально.

```bash
# Только пересчёт и сравнение байтов; без записи и сети:
PYTHONDONTWRITEBYTECODE=1 python3 -m benchmark.extended --check

# Восстановление генерируемых JSONL и PNG (перезаписывает эти файлы):
PYTHONDONTWRITEBYTECODE=1 python3 -m benchmark.extended

# Валидация и прогноз расходов, без API:
python3 -m benchmark plan --cases benchmark/extended/data/cases.jsonl --split dev

PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v \
  test_jev_router test_benchmark test_benchmark_scoring test_benchmark_extended
```

`original-data-lock.json` фиксирует хеши прежнего JSONL и assets. Тесты проверяют сохранность оригиналов, формат, отсутствие пересечения ID, загрузку image-only и offline-планирование.

## Планирование и завершённая оценка

При текущем конфиге: 84 ответа основных моделей плюс Jev и анализ изображений; планировочный резерв **406.30 RUB**. Это эвристический запас с fallback и base64, не ожидаемое списание и не жёсткий лимит. Прогон завершён: [итоговый отчёт](../results/evaluation-2026-11-15.md). Набор не менялся после оценки.

Для первого знакомства лучше выбрать фиксированный поднабор по категориям **до** просмотра ответов моделей, а не обязательно запускать всё. Не делать выводов по лучшему из нескольких прогонов. Финальный test не использовать для настройки.

## Ограничения

- Ответы короткие и проверяются exact/JSON; нет инструментов, реального исправления репозитория, sandbox-execution и длинных диалогов.
- Всё на русском, кроме инструкций на части PNG. Картинки чистые синтетические: не реальные фото или плохие сканы.
- Даже правильный короткий ответ не доказывает соблюдение алгоритма или способа рассуждений.
- Набор публичный, AI-generated, с общими авторами условий и проверок; генератор делает эталоны проверяемыми, но не гарантирует отсутствие неоднозначностей/ошибок модели задачи.
- Метрики старого пилота и extended не объединять без отдельного объяснения состава; пока сравнивать стратегии внутри каждого набора.
