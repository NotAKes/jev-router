# Безопасность

Jev Router — экспериментальный **локальный** прокси, не публичный API-сервис.

- По умолчанию слушает только `127.0.0.1`; не публикуйте порт в интернете и не меняйте bind без отдельной модели угроз, аутентификации и ограничений ресурсов.
- Встроенной клиентской авторизации, TLS, лимита размера тела и полноценной изоляции пользователей нет. Ключ сессии эвристический.
- `POLZA_API_KEY` храните в окружении. `.env.example` — шаблон, а не автоматическая загрузка: скрипт `.env` не читает.
- Полная история, изображения и инструменты запроса передаются внешнему провайдеру Polza и его upstream. Для описания изображения вызывается отдельная модель; её описание тоже уходит Jev. Не отправляйте секретные документы без согласования политики обработки данных.
- По возможности используйте встроенные data URI для изображений, не URL с секретными токенами доступа. Картинки не записываются прокси на диск, описания хранятся в ограниченном RAM-кеше. Это не гарантирует отсутствие хранения у внешних провайдеров.
- Стандартный stdout прокси содержит фрагмент пользовательского запроса, а обработчик ошибок может содержать фрагмент ответа upstream. Не считайте его безопасным для публикации. Бенчмарк сохраняет ответы локально; `benchmark/runs/` исключён из Git.
- Описание картинки — недоверенные данные. Защитные инструкции снижают риск prompt injection, но не устраняют его. Подключённые к клиенту инструменты требуют собственных проверок прав.
- Локальный планировщик расходов не гарантирует предел списаний у провайдера. Используйте отдельный ограниченный ключ/лимит баланса, если такая возможность доступна.
- Офлайн-тесты не требуют ключа и не должны обращаться к API. Реальные benchmark run и `test_routing.py` платные.

## Сообщение об уязвимости

Не публикуйте рабочий ключ или приватные данные в issue. Используйте private vulnerability reporting GitHub, если владелец включил его. Если приватного канала нет, сначала оставьте минимальный запрос о безопасном канале связи **без подробностей эксплуатации и секретов**. Скомпрометированный ключ следует отозвать, независимо от удаления файла из Git.
